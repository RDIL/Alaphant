# Obfuscated package segments whose real name is known.
#
# `generateIntermediary` turns an obfuscated segment into `pkg_N` because its real name is
# unknown -- the same reasoning that turns an obfuscated class into `class_N`. When the name is
# known, `pkg_N` is as wrong as `class_920` was for `Main`, and worse: a package is a runtime
# access boundary, so recovering it one class at a time in the named store splits the package and
# turns package-private references into `IllegalAccessError`. Recovering it here moves the whole
# package at once, and `checkLinkage` proves the result still links.
#
# Most names below come from the fully-qualified class names Charles' Lombok `@Slf4j` loggers
# leave in the constant pool, and every literal in the package agreed. The count is how many said
# so. That is the strongest evidence there is, and the first thing to look for.
#
# A package holding no literal can still be named, on the weaker basis that its whole contents are
# identified and a real word serves a reader better than `pkg_N` -- the comment then says what was
# known instead of a count. Certainty is not the bar; recording the evidence is. Say what it was, so
# a later reader can weigh a shape-based name differently from a logger-backed one and can re-check
# it -- naming a package renames every class in it at once, which is a reason to write the reasoning
# down, not a reason to leave the package as `pkg_N`.
#
# THIS FILE KEYS ON OFFICIAL NAMES AND GOES ENTIRELY STALE ON A CHARLES UPGRADE. Regenerate it
# from the new jar before `generateIntermediary` -- see step 6 of docs/charles-upgrade.md.
# Regenerated for 5.2.1; the obfuscator's segment pool churned wholesale (`MkAr` -> `sdfE`,
# `xvJk` -> `fuyF`, `Jpqc` -> `tZmD`, `vGmK` -> `eTgW`, `rkIB` -> `RqPz`).
#
